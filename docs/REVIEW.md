# 10ペルソナ・100観点の静的レビュー記録

## 数え方と限界

10種類の利用者・専門家を想定し、各ペルソナで10テーマを確認しました。`10ペルソナ × 10テーマ = 100チェックポイント`です。

これは実在する100人のレビューでも、Windows版Excelで100回実行した結果でもありません。ソース、コメント、文書を対象にした疑似ペルソナの静的レビューです。VBEコンパイルと32bit／64bit実通信は[`TESTING.md`](TESTING.md)に未確認として残しています。

## 各ペルソナで確認した10テーマ

1. READMEだけで目的と対象環境が分かるか
2. `.bas`取込みと最初の実行手順が再現可能か
3. VBA7の32bit API宣言が妥当か
4. VBA7の64bit API宣言と構造体配置が妥当か
5. IPv6アドレス、ポート、ループバック制限が明確か
6. TCPの接続、部分送信、分割受信、終端処理が妥当か
7. エラー、タイムアウト、ソケット、Winsockの後始末があるか
8. TraceIdと8列ログで両側を対応付けられるか
9. 受信値を数式や秘密情報として危険に記録しないか
10. 教材の制限、セキュリティ、実機未確認範囲が明記されているか

## クロスレビューで修正した主な事項

| 指摘 | 判定 | 修正内容 |
|---|---|---|
| WSADATAの固定長`char`配列 | 修正 | VBA固定長Stringを使わずByte配列にし、32bit=400／64bit=408をAPI前に検査 |
| 使用中ポートの共有 | 修正 | `SO_REUSEADDR`を廃止し、`SO_EXCLUSIVEADDRUSE`で排他的にbind |
| 別Excelの寿命 | 修正 | 起動元のモジュール変数でExcel／Workbook参照を保持し、明示終了マクロを追加 |
| 1回の`send`で全送信できるという仮定 | 修正 | 送信済みバイト数を加算し、全量まで繰り返す |
| 1回の`recv`で全文受信できるという仮定 | 修正 | LFまで複数回受信し、新規受信範囲内の最初のLFを走査 |
| 不正なTraceId | 修正 | サーバー採用文字を英数字・ハイフン、最大128文字へ制限 |
| 応答の取り違え | 修正 | クライアントで応答TraceIdと要求TraceIdを照合 |
| Traceシート保護時の二次障害 | 修正 | `Debug.Print`を先行し、シート書込みだけをエラー隔離 |
| 数式としてのログ実行 | 修正 | A:Gを文字列形式にして`Value2`で記録 |
| 日本語コメントの文字化け | 文書 | UTF-8→CP932変換またはVBE貼付け手順をREADMEへ追加 |
| TCP／UDP版の同名マクロ | 文書 | 両リポジトリを同一ブックへ混在させないよう明記 |
| 実機未確認の誤認 | 確認 | READMEとTESTINGにWindows Excel未実施を明記 |

## 実機で残る確認

- Office 32bitと64bitの両方でVBAProjectをコンパイル
- `CheckTcpIPv6StructureSizes`の成功
- `[::1]:60052`のHELLO、日本語ECHO、QUIT
- 接続失敗、受信タイムアウト、ポート競合
- サーバー専用Excelの起動・保持・終了
- 保護されたTraceシートでもソケットが後始末されること

実機結果は、Officeのビット数、Windows／Excelのバージョン、Trace、Winsockエラー番号とともに追記してください。
